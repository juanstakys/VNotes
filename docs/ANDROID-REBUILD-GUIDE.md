# VNotes native Android reconstruction guide

Version 3.3.1. This guide describes the Kotlin port independently of the PWA guide. A programmer can rebuild the native application without an LLM. The original PWA lives under `web/`, with its original code preserved; native Android is the primary project under `android/`.

## Product and visual contract

Keep the approved minimalist sketch: white background, two equal top tabs TODO/DONE, mint selected tab, plain note rows with separators, no title/description/count/timestamp. Settings is a circular icon at the bottom left. Center is the rounded text input; right is the shared microphone/plus/stop icon. While recording, replace the input with an energy level meter and elapsed time; display a revisable live transcript immediately above the bottom controls. Keep partial words out of the durable note list until recording ends. Show a separate Cancel only when recording/processing. DONE replaces the composer with a permanent erase-all control. Keep functional dialogs, model setup, errors and retry messages; do not add promotional copy.

Both lists anchor their content at the bottom of the available scroll viewport while short, leaving unused space above. New additions appear at the top of that bottom-anchored group and grow it upward. Once the group exceeds the viewport, use normal vertical scrolling, keeping newest first and scrolling to the top on additions/import/tab changes. Implement with ScrollView.fillViewport=true and a single vertical LinearLayout child with gravity=BOTTOM; do not reverse the data or reverse the scroll origin. Active notes sort newest first. Type-add trims outside whitespace and preserves internal newlines; text limit 20,000 characters. Editing preserves list position. Completing a note moves it to DONE. DONE is soft deletion, sorted by latest completion. Restore sets creation time to now so it appears at top. Swipe right on an active item -> mark DONE. Swipe left anywhere in the main Activity (including blank space, rows, tabs and composer) -> switch to DONE. Swipe right anywhere in DONE -> switch to TODO, with no restoration/deletion side effects. Left in DONE does nothing. Editing is only available through the item ellipsis menu -> Edit -> Type/Record; tapping the row itself does not open the edit menu. Restore and individual permanent erase use the DONE ellipsis menu; the bottom trash button erases all DONE notes with confirmation. A non-modal snackbar immediately above the input follows reversible moves, with its UNDO button aligned right. Canceling edit/record does not alter the original. Recorded replacement opens editable review with Save, Record again and Cancel.

English recognition, no accounts/analytics/sync/cloud inference. Initial model download is allowed, then app works offline. Notes are private to the app. Export/import backups use Android's system document picker. Export the PWA JSON and import it into Android to transfer data; browser storage cannot be read directly by the native application.

## Build and packaging contract

Use Kotlin and native Android views, not WebView, HTML, JavaScript, Compose or a browser-dependent capture API. Use AppCompatActivity and programmatic native views with explicit androidx.appcompat:appcompat:1.6.1 and com.google.android.material:material:1.10.0 dependencies (already compatible with the speech SDK). Original mode uses simple LinearLayout/ScrollView/EditText/Button controls and AppCompat dialogs; Material mode uses real Material components. Native speech SDK also brings AndroidX/OkHttp dependencies.

Pinned tools: JDK 17, Gradle 8.9, Android Gradle Plugin 8.7.3, Kotlin 2.0.21, compile/target SDK 35, min SDK 26 (Android 8.0). Dependency: `ai.moonshine:moonshine-voice:0.1.5`. Repository sources: Google Maven, Maven Central, Gradle plugin portal. Use the Gradle wrapper under android/. The build helper generates a standard debug signing key once in ignored android/.signing/debug.keystore, builds/tests, copies the APK into releases/ and records SHA-256. Keep this key for compatible future debug upgrades; production needs a separate private release key. Debug credentials are the public Android standard and provide no release identity.

The universal test APK includes arm64-v8a, armeabi-v7a, x86_64 native libraries. Legacy native packaging extracts compressed .so files at install; no model weights are bundled. Files under releases/ are deliverables, while local.properties, .gradle, build outputs, IDE state and signing keys are ignored. Debug app id is app.vnotes, version code 5, version name 3.3.1. Android manifest declares microphone and internet access. No storage permission is needed for private files or document pickers. Do not permit cleartext network requests. Android backups are disabled so the model/audio is not automatically uploaded by the app backup mechanism; users export explicit JSON backups.

Theme is a light native no-action-bar theme, white system bars on API27+ and green accent (API26 retains a dark navigation bar for visible system buttons). Keep newer theme attributes in values-v27 and values-v35 resource folders, with common attributes in the base style. Set adjustResize for keyboard. On API 35, this build opts out of enforced edge-to-edge to keep system bars/keyboard from covering controls. Handle orientation/screen/keyboard configuration changes in the Activity, and stop capture when leaving foreground. Font/icon drawing and min 44dp controls should remain accessible. Keep theme constants in MainActivity's small color palette and styles.xml.

## Modules

- MainActivity.kt: native UI construction/state, screen-wide dispatchTouchEvent routing, right-swipe TODO completion, dialogs, permission flow, settings, capture coordination, retries, executor orchestration, SAF backup import/export.
- SwipeNavigation.kt: pure horizontal direction/threshold policy, shared by Activity and row gesture handling and covered by JVM regressions.
- UndoSnackbar.kt: transient non-modal bottom bar, message weighted left and UNDO right; lives directly before the bottom controls in the resize-aware vertical layout.
- NoteStore.kt: SQLiteOpenHelper and Note model, versioned JSON parser/merge, PendingAudio/RetryStore atomic file storage.
- EnergyVad.kt: sample-duration energy VAD, logarithmic sensitivity and meter mapping, quiet-boundary long-audio segmentation. No Android imports; unit-testable on JVM.
- AudioCapture.kt: native mono PCM AudioRecord capture, RMS, test mode, stop/release lifecycle, two-minute bound.
- SpeechEngine.kt: native Moonshine setup/presence/loading, incremental stream sessions and segmented saved-audio fallback, used exclusively from one executor.
- LiveSpeechSession.kt: bounded immutable audio submission on the serial executor, ordered start/feed/final-flush, cancellation, error handoff and late-event guards.
- LiveTranscript.kt: copy text by line ID and chronology, replacing changing hypotheses rather than appending duplicates.
- res/drawable/ic_launcher.xml: vector launcher monogram. res/values/styles.xml: native light theme.
- src/test/.../EnergyVadTest.kt: pure signal/duration/segmentation regressions.

The app does not require an HTTP server, adb reverse, Chrome, Firefox or WASM. ADB is only an optional installation/logging/testing tool.

## Native audio and energy VAD

Use AudioRecord with AudioSource.VOICE_RECOGNITION, mono CHANNEL_IN_MONO, PCM_16BIT, 16,000 Hz. Ask for RECORD_AUDIO at runtime before creating the recorder. Check getMinBufferSize returns a positive value, allocate at least max(minimum*2,4096) bytes, verify STATE_INITIALIZED, startRecording and verify RECORDSTATE_RECORDING. Report initialization/read errors instead of returning empty notes.

Read on a dedicated thread into 512-short blocks. Convert each short to normalized float with sample/32768f. RMS=sqrt(sum(value²)/count). Each actual frame count contributes count*1000/16000 milliseconds. Keep cumulative speechMs (RMS>=threshold) and current continuous quietMs. Above threshold resets quietMs, below adds to it. Require at least 300ms of above-threshold audio before arming automatic stop. Auto-stop when armed and quietMs>=silenceSeconds*1000. Leading silence and a brief click alone do not trigger stop. Default silence is 2 seconds; settings choices .7,1,2,3,5 seconds.

Sensitivity slider has 1001 positions (0..1000). RMS threshold = clamp(.1*10^(-position/250),.00001,.1), so rightward is more sensitive. Default .01 corresponds to position250. Store the numeric threshold, not the slider position. Meter position = clamp((20*log10(max(.00001,RMS))+100)/100,0,1). Settings displays the threshold marker on the same log scale, raw RMS, and above/below text. The test uses exactly the same capture source/constraints but never allocates a take buffer, saves PCM or invokes inference. Changes apply immediately to its comparison feedback and to the next recording.

A normal capture allocates at most 120*16000 floats (~7.7 MB). Stop at two minutes, on manual action, on Cancel, or when the Activity leaves foreground. Atomic flags coordinate the UI and read thread. Stop unblocks a blocking read; release the recorder in a finally block. Ignore the expected read failure after a requested stop. Cancel emits no audio. Manual stop allows quiet speech with peak>.0005 and >=150ms captured even if the automatic threshold never armed. Fully silent audio is discarded. The capture callback persists usable PCM before posting a UI callback, so finishing an Activity cannot discard an already completed take solely because UI delivery was skipped.

No AudioTrack, microphone loopback, native speech recognition intent or cloud API is involved. The microphone settings test must stop on dialog dismissal/app background. On interruption or permission rejection show an actionable error. If the device cannot initialize 16kHz capture, this version reports it; it does not silently fall back to a mislabelled sample rate.

## Moonshine native setup and inference

Use the official native Android SDK rather than porting Transformers.js. Native models are ORT-format assets and tokenizer data, distinct from the web ONNX model cache. Construct `ModelSpec.stt("en", JNI.MOONSHINE_MODEL_ARCH_TINY, false)` to choose the original small English Tiny architecture explicitly and omit spelling/diarization extras. Model root: filesDir/models/moonshine-tiny-en.

Call AssetDownloader.isModelPresent(root,spec) on the speech executor during initial startup. This resolves the compiled native file catalog and checks local files. Initial setup calls ensureModelPresent(root,spec,progressListener), whose HTTPS transfers use .part files, support HTTP Range resume, check space, and rename completed downloads. Display file progress on the main thread. Then construct `Transcriber(listOf(TranscriberOption("decode_incomplete_lines","true")))` and loadFromFiles(root.absolutePath, JNI.MOONSHINE_MODEL_ARCH_TINY). Explicit incomplete-line decoding makes the existing Tiny model produce hypotheses before speech ends. Declare setup successful only after loading succeeds. Keep all native methods on one executor. The engine is closed after each live take because the SDK retains completed-line event PCM; later takes reload from local model files without another network download. Also close it when the Activity shuts down after queued work.

For saved-audio fallback/Retry, feed float PCM into transcribeWithoutStreaming(segment,16000), then use transcript.text().trim(). Split takes exceeding 20 seconds explicitly: search 250ms windows from 12..20 seconds and cut at the midpoint of the quietest window (latest on ties). Every sample belongs to exactly one segment; no overlap or loss. Process segments sequentially and join nonempty texts with spaces. Quiet-boundary splitting reduces but cannot eliminate mid-word cuts. Reject empty final output as a retryable failure.

Cancellation never frees a JNI object from another thread. For live recognition, cancel immediately marks queued audio unwanted; any in-flight native call returns before serial cleanup. During finalization, keep saved audio for Retry and re-enable controls when cleanup finishes. Saved-audio fallback cancellation remains cooperative at operation completion. Do not close/free JNI objects from a second thread while inference runs. Typed entry remains usable while inference/model setup runs. New microphone recording is blocked until the speech operation completes.

## Durable storage and backups

SQLite database vnotes.db, schema version1:
`notes(id TEXT PRIMARY KEY, text TEXT NOT NULL, created INTEGER NOT NULL, updated INTEGER NOT NULL, deleted INTEGER)`.
Null deleted means active. UUID ids, epoch millisecond timestamps. Preserve existing text/settings during updates. Use database transactions for bulk import. Import only missing IDs; do not overwrite matching local IDs or current settings.

SharedPreferences file settings contains float threshold and silence, plus boolean material3 (default false). Clamp threshold into [.00001,.1] on load. Persist changes immediately. No speech or note text goes into logs/analytics.

RetryStore uses Android AtomicFile at filesDir/pending-audio.bin. Format: big-endian int magic0x564E4131; Java DataOutput UTF note UUID; UTF edit target UUID or empty; int sample count; sampleCount float32 values in big-endian. Valid size 1..1920000. The note UUID is generated when creating the pending take and remains stable across retries; insert/replace by that same ID prevents duplicate notes if cleanup is interrupted after save. For an edit, target identifies the existing note and the transcript is reviewed before changing it. Successful transcription/review handoff clears the retry file; unsuccessful/cancelled inference retains it. Discard deletes it explicitly. Never create an empty note or lose typed draft before successful SQLite write.

Backup JSON retains the PWA format: format="vnotes", version=1, notes=[{id,text,createdAt,updatedAt,deletedAt}], settings={silence,threshold}. Export via ACTION_CREATE_DOCUMENT. Import via ACTION_OPEN_DOCUMENT, read at most ~10MB into memory with an explicit bounded loop compatible with API26. Validate count<=50000, unique nonblank IDs, nonblank text<=20000, finite positive date-range timestamps, null deletedAt or valid timestamp. Preview the count of missing IDs before import. Browser data does not migrate implicitly. Export files are user-owned outside app-private storage and survive uninstall.

## Rebuild sequence and acceptance

1. Create Gradle project and manifest/theme/vector icon with pinned versions above.
2. Implement pure VAD/slider/segmentation and JVM tests.
3. Add SQLite and retry atomic file; implement typed TODO/DONE actions and backups.
4. Construct minimal native-view AppCompatActivity and dialogs; wire gestures and accessible row/action alternatives.
5. Add runtime permission, AudioRecord capture/test and deterministic cleanup.
6. Add native Moonshine downloader/load/offline inference on a single executor.
7. Build debug APK, run tests, verify signing/manifest/ABIs, record checksum and install on a real phone.
8. Verify cold airplane-mode relaunch/transcription after setup, Android permissions denied/granted, soft/noisy speech, manual stop/silence/cancel/two-minute/background behavior, recorded-edit review, swipe/menus, backups/PWA migration, process restart with retry audio, keyboard layout, TalkBack and large text.

Compilation/JVM tests do not verify phone microphone hardware or actual Android JNI inference. Record observed checks and limits in ANDROID-VALIDATION.md; never imply device validation from an APK build alone.

Official API references: https://github.com/moonshine-ai/moonshine/tree/main/language-bindings/android and https://github.com/moonshine-ai/moonshine/tree/main/examples/android/Transcriber . Pin release APIs using Maven's 0.1.5 sources JAR when reconstructing; main may change. SDK is MIT; transitive ONNX Runtime and other licenses remain in upstream distributions.

## Screen-wide gestures and snackbar (3.1)

Observe events in Activity.dispatchTouchEvent so empty space and controls participate; an OnTouchListener on rows alone is insufficient. Track raw start coordinates and selected tab on DOWN. Above 12dp choose horizontal intent only if abs(dx)>1.3*abs(dy); latch vertical intent to preserve normal scrolling. Navigation direction is left from TODO or right from DONE. Once intercepting, send a copied ACTION_CANCEL to the normal child dispatcher and consume the rest of the gesture, preventing incidental button activation, text selection or row completion. At UP, navigate if displacement exceeds 80dp and still has horizontal intent. Multi-touch and cancelled gestures do not navigate. Dialogs have their own Window and retain slider/text-edit gestures. Recording/finishing blocks tab changes. Switching to DONE preserves the draft but dismisses its keyboard.

TODO row handling only translates right and completes after a qualifying right swipe. DONE rows have no swipe mutation handler; they expose actions through ellipsis only. Left on TODO can never edit and right on DONE can never erase or restore. Keep the menu button as the sole edit entry point.

The snackbar is a native horizontal LinearLayout, dark ink background, readable message and mint UNDO button at right, inserted immediately above the composer controls rather than an AlertDialog. It never steals input focus. Show for 6 seconds, extended with AccessibilityManager.getRecommendedTimeoutMillis on API29+ or 15 seconds for touch exploration on older Android. Mark the bar a polite accessibility live region. Replace an existing action when another move happens; cancel callbacks on dismissal/detach/app background. Undo restores only created/deleted fields on the current stored note, retaining later text edits. If the note no longer exists, do not resurrect it. Permanent erasure also dismisses any outstanding snackbar.

## Live transcription (3.2)

Use the same native Tiny model and existing model directory. No new model architecture or download is necessary. AudioCapture exposes an onAudio callback only in recording mode; copy each captured normalized PCM prefix before handing it off, including a clipped final block. Settings microphone tests never invoke this callback or feed the model. Continue retaining the full two-minute-bounded take for durable retry. Write retry files through BufferedOutputStream before AtomicFile.finishWrite so per-float writes do not stall the stop path; the file format does not change.

Create LiveSpeechSession on the UI thread with the existing serial speech executor. Queue backend start before any feeds. Offer clones the block and enqueues feed without running inference on the microphone thread. Limit total queued samples to 1,920,000 (120 seconds at 16 kHz). The recorder continues independently while the model processes its backlog; weak phones may show delayed updates.

Backend start: load the native engine with decode_incomplete_lines=true, remove previous listeners, setUpdateInterval(.5), attach a listener and call Transcriber.start(). Feed invokes addAudio(block,16000). The SDK adapts its decode interval to measured processing cost, rather than making the capture thread wait. Listen to LineStarted/LineUpdated/LineTextChanged/LineCompleted, copy line ID/startTime/text immediately, and replace that line’s entry in LiveTranscript. Sort by start time then ID and join nonempty line texts. Emit only changed full hypotheses. Do not retain the event’s raw audioData or append repeated partial strings to the note.

On Stop or energy-based silence, persist the usable raw take, mark finalization busy and queue session.finish behind all audio feeds. Native stop forces the trailing phrase to be analyzed; return the accumulated final text and remove listeners/close the native engine in finally. Save a new note exactly once through the existing stable pending UUID, or show the existing record-edit review dialog. Clear retry audio after successful save/review handoff. If streaming fails or returns no words, close the failed stream and reuse the existing saved-audio transcription path. Its errors still leave Retry/Discard available.

Cancel recording invalidates UI callbacks, discards the take and preview, and queues serial cleanup; it saves no note. Cancel during finalization skips queued feeds, waits for an active call and preserves the already saved take. A finished session ignores late hypotheses and late cancellation so it cannot close the next session’s engine. Activity generation tokens prevent old partials from overwriting another take. On Activity destruction, stop the recorder, cancel the live session before shutting down the executor, then close native state on that executor.

Display live text as a noneditable, vertically scrollable, at-most-five-line TextView above the bottom controls. Scroll it to the newest words after revisions. Keep the audio bar/timer in the input’s usual slot. Hide/clear the preview after final save, review handoff, cancellation or failure, and start each take with a fresh accumulator. Existing TODO/DONE navigation, snackbar and sensitivity behavior remain intact.

Additional JVM regressions use a deterministic serial executor and fake speech backend: partials arrive before Stop; offered PCM is immutable; every feed precedes final flush; cancellation skips queued work and suppresses late updates; stream errors produce a recoverable final result; the take limit bounds queued samples; hypotheses revise by line ID without duplication. Actual Android speech accuracy/latency must still be checked on a phone.


## Two complete native designs (3.3)

Original Design remains the default on fresh installs and upgrades. Settings contains a toggle labeled Material Design 3 with the explanation that off uses Original Design. Save boolean material3 in the existing settings SharedPreferences immediately. Apply the selected theme before super.onCreate. Switching dismisses settings and recreates the Activity, preserving draft text and TODO/DONE selection through onSaveInstanceState; reopen Settings after model presence checking so the toggle remains easy to reverse. Disable design changes during recording/finalization/model setup/transcription to avoid interrupting native work. Existing notes, model files and audio settings are independent of the visual preference. Backup import still preserves local settings; model download is never required to change design.

Use Theme.AppCompat.Light.NoActionBar for Original and Theme.Material3.Light.NoActionBar for Material. Keep the Material color roles centrally editable in res/values/material3.xml, with API27/API35 system-bar overrides in qualified folders. Retain the Original palette and rounded mint circular icon buttons. Material mode uses semantic color roles, MaterialTextView, TextInputLayout/TextInputEditText for composer and edit/review fields, segmented MaterialButtonToggleGroup tabs, outlined MaterialCardView note rows, 56dp FloatingActionButtons, MaterialButton actions, MaterialAlertDialogBuilder for every dialog, MaterialSwitch, Slider and an outlined exposed MaterialAutoCompleteTextView dropdown in Settings. Programmatically constructing platform widgets under a Material theme alone does not create Material components; instantiate the matching classes explicitly. NoteIconDrawable shares microphone/plus/stop/settings/trash symbols between the two designs.

The recording level meter and live text follow the selected palette; the recording meter still replaces the composer. Original mode retains the custom bottom UndoSnackbar. Material mode uses the library Snackbar anchored to the composer controls, with message left and UNDO right. Dismiss the active snackbar on background/permanent erase. Gestures, edit review, model setup, keyboard resizing, retry and backup operations use the same behavior in both styles.

DesignUiTest uses Robolectric 4.14.1/API28 to exercise real Activity/theme resources, newest-first ordering and measured bottom anchoring, Material controls in the main screen/settings, persisted switching and draft/tab restoration. These tests do not verify phone rendering, touch hardware or native speech inference; check both designs on Android before treating them as device-validated.


## Sliding navigation and whole-item dragging (3.3.1)

Keep the top tabs fixed. Put the scrolling note page in a clipped FrameLayout (NotesHost) above the fixed bottom controls. Both tapping a tab and completing a navigation swipe call the same switchScreen function. TODO -> DONE moves the old page left and brings the new page in from the right; DONE -> TODO reverses these directions. Rebuild the destination ScrollView using the same bottom-anchored content factory, render its notes and reset its scroll to newest. Retain the outgoing page only during a 220ms horizontal ViewPropertyAnimator transition with DecelerateInterpolator; animate both pages by one viewport width. Use real views rather than bitmap screenshots so long lists do not allocate screen snapshots. Skip animation before layout and when Android disables animators.

Before another transition or app backgrounding, invalidate the previous completion callback, cancel animations, discard every stale page and reset the current translation to zero. The animation end callback uses a generation token so a cancelled transition cannot remove the new page. NotesHost intercepts child touches during the slide so the outgoing list cannot receive edits/completion gestures; tabs and screen-wide navigation remain available for reversal. Hide outgoing descendants from accessibility until removal. Bottom composer/settings/action controls update for the destination tab and stay fixed.

Build each item as one outer view. Material mode uses the MaterialCardView containing the row; Original uses a vertical wrapper containing the row and its separator. Observe TODO-body drag events on the inner row, but set translationX on this outer view. That moves text, ellipsis menu, background, border and separator together. Preserve existing direction/vertical-intent/80dp completion rules; reset translation on up/cancel/multiple pointers. Permanent erase and edit remain menu/button actions. A successful completion saves the note and displays the existing undo snackbar.

UI regressions exercise full-card translation, cancellation restoring it, successful completion, both slide directions in both designs, and rapid tab reversal leaving exactly one page at translation zero. Existing state-restoration tests also remain required.
